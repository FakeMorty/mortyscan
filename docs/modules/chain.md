# `chain` — Attack Path Correlation

Постпроцессор сопоставляет независимые findings с декларативными правилами из `mortyscan/data/chains.yaml`. Модуль не делает HTTP-запросов, не использует эвристические `eval` и не запускает эксплуатацию.

- Каждое правило задаёт список условий по полям `module`, `type`, `tag_any`, `title_contains_any`, `title_requires_any`, `evidence_contains_any`, `raw_path_contains_any` и `url_path_contains_any`.
- По умолчанию разные условия должны подтверждаться разными finding. Только `allow_same_finding: true` разрешает одному finding удовлетворить несколько условий.
- Срабатывание создаёт `Finding(type="attack_chain")` со ссылками на ID исходных findings; встроенный набор содержит 10 правил.
- Severity цепочек задаётся в YAML. Текущие правила маркированы `critical` согласно спецификации, однако это корреляционные гипотезы: итоговую применимость нужно подтвердить вручную.
- Запускается как постпроцессор после остальных модулей, в том числе когда задан фильтр `--modules`.

PyYAML входит в зависимости пакета. При отсутствующем или повреждённом YAML файл сканирование продолжается без корреляции и добавляет информационное finding. Для тестов путь к правилам можно передать через `chain_rules_path` в конфигурации.
